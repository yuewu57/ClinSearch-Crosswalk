# Licensing and public-release review

## Current status

ClinSearch-CrossWalk is source available under the PolyForm Noncommercial License 1.0.0. It is not OSI-approved open-source software. Public release still requires confirmation that the project has authority to distribute all included copyrightable contributions and third-party materials.

Repository control or manuscript authorship does not by itself establish software/IP ownership. No ownership transfer to a company or other organisation is asserted here.

## Public wording

Use:

> Source available under the PolyForm Noncommercial License 1.0.0. Uses outside its permitted purposes require a separate licence from the relevant rights-holder.

Do not describe the software as open source unless the rights-holders deliberately relicense it under an OSI-approved licence.

The unmodified official licence text in `LICENSE` controls. Its organisational permissions are broader than a blanket "no commercial context" summary, so public descriptions should not replace the licence with an inaccurate shorthand.

## Checks before publication

1. Confirm ownership/authority for university, employee, student, contractor and collaborator contributions.
2. Identify third-party code, datasets, terminology and images and preserve their applicable licences/notices.
3. Review whether earlier versions were distributed under Apache-2.0 or another licence; a later licence change does not revoke an earlier valid grant.
4. Review the exact release tree for credentials, confidential material and redistribution restrictions.
5. Confirm approved software contributor metadata separately from manuscript authorship.
6. Freeze and archive the exact tested source commit and terminology cache.
7. Review the chosen static hosting provider's terms, logging and analytics behaviour.
8. Add the actual release date, repository/public application URL and archive DOI only when established.

The static browser architecture performs conversion locally. The host may still log ordinary page and asset requests, so privacy statements should distinguish local strategy processing from provider-level access logging.
